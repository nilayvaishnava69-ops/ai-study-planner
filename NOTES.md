# Accessible Components Notes

## Overview

This assignment compared manually built accessible React components with components generated by shadcn/ui.

The manually built components are:

- Modal.tsx
- Tabs.tsx
- Disclosure.tsx

The shadcn components inspected are:

- components/ui/dialog.tsx
- components/ui/tabs.tsx

## Difference 1: Dialog Implementation

The manual Modal component implements dialog behavior directly using React hooks such as useEffect and useRef.

The manual implementation explicitly handles:

- Escape key closing
- Tab focus trapping
- Shift + Tab reverse navigation
- Initial focus
- Returning focus to the previously focused element

The shadcn Dialog implementation delegates the dialog behavior to Base UI through:

@base-ui/react/dialog

The generated component wraps primitives such as:

- DialogPrimitive.Root
- DialogPrimitive.Trigger
- DialogPrimitive.Portal
- DialogPrimitive.Backdrop
- DialogPrimitive.Popup
- DialogPrimitive.Close

Therefore, the manual implementation contains the focus-management logic directly, while the shadcn implementation relies on the underlying Base UI dialog primitive.

## Difference 2: Tabs Architecture

The manual Tabs component is one component that receives a tabs array and manages the active tab using React state.

It directly implements keyboard navigation for:

- ArrowRight
- ArrowLeft
- Home
- End

The shadcn Tabs implementation delegates tab behavior to:

@base-ui/react/tabs

and exposes separate components:

- Tabs
- TabsList
- TabsTrigger
- TabsContent

Therefore, the manual version combines the tab structure and behavior into one component, while shadcn separates the tabs into reusable building blocks.

## Difference 3: Styling

The manual components use Tailwind CSS class strings directly.

The shadcn Tabs implementation additionally uses:

class-variance-authority

through cva and VariantProps to provide style variants.

For example, the generated TabsList supports:

- default
- line

This makes the generated component more configurable from the outside.

## Conclusion

The manual components demonstrate how accessibility behavior can be implemented explicitly with React state, refs, keyboard events, and ARIA attributes.

The shadcn components provide a more reusable component architecture and delegate accessibility behavior to Base UI primitives instead of implementing all interaction logic directly inside the component.
